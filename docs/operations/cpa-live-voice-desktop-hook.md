# Desktop voice procedure and support

CodexHost keeps native Chat Instant Connect and Work gateway voice on the official Desktop. It does not rewrite `app.asar` or replace `/Applications/ChatGPT.app`. Audited identities live in `packages/renderer-extension/src/renderer-voice-profiles.ts`. Discovery never activates a profile.

Historical export mappings and older incidents: [cpa-live-voice-desktop-hook-history.md](cpa-live-voice-desktop-hook-history.md).

## Current procedure

1. Confirm the launched Desktop **product version**, **platform**, **native build**, **asar digest**, and **app path**. Managed launch writes those from the discovered installation (`apply_managed_desktop_identity`). Inherited `CODEXHOST_DESKTOP_*` values cannot impersonate a different install. An owned isolated Controller is not the Desktop child: LaunchServices+Shim strip `CODEXHOST_*` from that Desktop, so the Node Controller spawn must set `CODEXHOST_DESKTOP_VERSION`, `CODEXHOST_DESKTOP_BUILD`, `CODEXHOST_DESKTOP_ASAR_DIGEST`, and `CODEXHOST_DESKTOP_APP_PATH` from the launched scratch bundle. That app path must not be `/Applications/ChatGPT.app`. Hashes name assets; they do not prove export meaning or a connected call.
2. Production startup checks reviewed identity, the build-time implementation revision, native artifact identity, and assets cheaply. The implementation revision is a hash of the voice implementation source graph, baked before compile; it is not a digest of profile metadata, and production does not scan source at runtime. Profile digest remains a separate pin of the selected owner table. Native Chat START is bounded; a timeout aborts the owned native signal, keeps ownership of the uncertain native write, and ignores late results. Installer and npm payloads copy `app/voice-profile-pins.json` and `app/voice-qualification.json` next to the Renderer and validate them against current source identity and that implementation graph before archive. A packaged Controller with a Desktop version set does not fall back to in-process pin lists when those files are missing or corrupt. Empty `reviewedEvidence` is honest; it does not fabricate attended qualification.
3. For a new Desktop, run maintainer discovery against an explicit candidate inventory (`npm run voice:discovery -- --inventory <json>`). Structural similarity is a candidate, not activation. When source bytes are present, the maintainer CLI derives AST facts and rejects a supplied role interpretation that contradicts those bytes. Replay descriptors without bytes keep caller structure as snapshot assertions, not fresh byte-verified role ownership. Session-method role evidence (`dispatchVoiceCommand`, `startVoiceWithIntroduction`) is bound only to the verified `initializeVoiceSession` export/result graph, not to other exported helpers. Duplicate factories collapse only when module id plus a scoped AST canonical digest match. That digest uses globally unique lexical binder IDs across nested function, block, class, catch, and for scopes, including destructuring aliases; an outer captured binder stays distinct from an inner parameter of the same minified name. Local alpha-renames with the same structure collapse. Same-shape copies with different bodies, require targets, literals, or control flow stay ambiguous. An overlay-scoped `voice-isolated-qualification.json` next to `--renderer` may enable one unqualified candidate path, or an explicit independently scoped `paths` set, for gathering evidence. It requires a finite parseable future `expiresAt` and an explicit `desktopPlatform` that matches the launched Desktop (`darwin` / `win32` / `linux`); a missing platform is not inferred — re-issue the ephemeral marker. If `paths` is present it must be a nonempty array of distinct known paths, consistent with `path` when both are set; malformed `paths` does not fall back to legacy `path`. Single-`path` markers remain valid. The marker never writes `reviewedEvidence`, does not match `/Applications/ChatGPT.app` or a Windows Store `WindowsApps\\OpenAI.Codex_` / `OpenAI.ChatGPT_` path, and is not a universal allow-all. `hashedVoiceProfileSupported` stays darwin-only; win32 26.1106.51428 is a hashed candidate owner so an exact isolated marker can apply. Production Windows Controllers keep the 26.1106 injection skip; an owned isolated Controller unskips only when that fully validated marker matches launched app/platform/build/asar/revision/path. A skip identity whose `desktopPlatform` or `desktopVersion` disagrees with the Controller arguments stays skipped. Saved Voice settings remain the requested Chat/Work product: ChatGPT Chat uses native WM, explicit Codex Chat uses the chosen desktop/gateway, Work/Codex uses the chosen desktop/gateway, and an external Harness uses the configured gateway. Switching the isolated path set is a test-setup action, not a user preference rewrite. Explicit isolated permission is not a pass. The Controller injects `isolatedQualification` only when that launched identity env, including platform, matches the marker. A valid file with incomplete identity env is not live CPA config on primary or overlay.
4. Qualify Chat and Work independently. Work records Codex and Grok separately. A passing Chat path does not enable Work or the other platform. Hashed 26.1106 Chat Instant Connect is composer web-backed WM (`__codexhostNativeChatVoiceV1`). Compact Voice `/wham` is Work gateway (or explicit Codex Chat gateway). A Work-only isolated marker leaves the Chat hook uninstalled; overlay Chat `/wham` must fail closed rather than passthrough to native/official CLI realtime. Owned ChatGPT Instant Connect `requestRealtimeStart` must not dispatch official overlay start when that WM hook is absent, pending, unsupported, or unqualified; explicit Codex Chat and Work remain on their native/gateway paths, and extension-disabled traffic is unwrapped. Shared `experimental_realtime_*` is the Work CPA pair; do not treat it as Chat native fallback, and do not edit production config to “fix” Chat. Repeated CPA `GET /v1/live` HTTP 404 with independent `GET /v1/responses` HTTP 200 localizes a handshake to the live sideband; it does not prove Host create ownership. Correlate gateway screenshots labeled ~02:44 with client ~03:44 JST as UTC+8 vs JST, not as a one-hour delayed event. Do not copy account, session, or call identifiers from those screenshots.
5. Require automated lifecycle/identity checks **and** attended two-way speech before reviewed activation. START acknowledgment, a button, a gateway-route event or a live audio track alone is not a pass.
6. If a path is unqualified or binding fails, disable that entry with a short reason. Do not substitute another product, Harness or route. Gate `missing-evidence` stays the internal debug code. Native toasts use `Work voice is not qualified on this Desktop.` or `Chat voice is not qualified on this Desktop.` when the hashed 26.1106 profile is present but that lane is not qualified. Desktop Voice settings keep Preferences applied as saved/applied, separate from selected-route readiness. Gateway configuration (Configured / Needs setup) can sit next to a qualified gateway route; that route line is Desktop permission, not a working-transport claim. Intentional Desktop default stays selected/native and is labeled Desktop default selected; it is not disabled because a gateway lane is unqualified, and it is not inspected native-call health. Qualified ChatGPT Chat or gateway routes use Allowed on this Desktop. The Voice page poll refreshes that selected-path status even when the Host get payload is unchanged. Hashed overlay ChatGPT Instant Connect `/wham` does not passthrough to native realtime. Explicit Codex Chat Desktop `/wham` stays native. Owned ChatGPT Instant Connect uses the same Chat sentence, or `Native Chat voice is unavailable` when Chat is qualified but the WM hook is not active, and does not open Compact Voice.
7. Sanitize evidence: profile/build/platform, path/Harness, stage/outcome codes and assertion booleans. No conversation IDs, SDP, tokens, transcripts or raw native exceptions.

Voice settings remain on the Desktop/console Voice page. ChatGPT Chat uses native START. Work uses the configured CPA gateway when selected. Saved `lastAgent` is not the selected Harness; official Codex stays selected when no current matching external carrier exists.

Production Host with no `--codex-home` uses the default user Codex home. The working saved profile selects `model_provider = "custom"` with a non-empty `name`, HTTPS `base_url`, `wire_api = "responses"`, `requires_openai_auth = true`, an in-file provider credential, matching HTTPS `experimental_realtime_*` origins, and `auth.json` `auth_mode = chatgpt`. `requires_openai_auth = true` on that custom provider is the stock working combination, not a conflict. Isolated Host **60916** (launcher **60909**) was `host restart`ed with `--data`/`--plugins` still isolated and `--codex-home` set to that same default user Codex home; argv `--stock-codex` is the scratch-bundle CLI from `official-startup-v1.json` (not a Node placeholder). Official Codex child **5011** inherits that home. The unused `isolated-cpa` native-home file remains gateway-transport-only; `inspectIsolatedNativeHomeToml` does not prove ChatGPT auth. Drop-Shim is not a Grok restore. Sharing the native Codex home is not a Host mutex: occupancy is per-thread flock; do not copy, write, or delete it. A Host-only `experimental_realtime_provider` split stays on hold.

## Support and evidence

Reviewed observations are stored in
`packages/renderer-extension/voice-reviewed-evidence.json`, outside the voice
implementation source graph. Renderer builds and release validation compose
`voice-qualification.json` from that data and the generated implementation
revision. Every record must use the reviewed policy and pass the current
evidence evaluator, including revision, profile, connection, attended speech and
cleanup checks. Editing evidence data does not change the implementation revision;
editing the evaluator, runtime or profile ownership still does. Release validation
compares staged evidence with this independently loaded source data. The registry records reviewed activation separately from the original attended
observations. Compatibility carry-forward records retain their original tested
revision and require an exact scoped review for the target revision.

The macOS acceptance baseline includes completed Chat existing/new/leave-return,
Work/Codex, and Work/Grok speech, End Voice and microphone-release checks on
Desktop 26.1106.51428. Preserve those observations with their tested revisions.
A package version change or a later incomplete test run does not erase them.
Promotion to another implementation revision requires a scoped compatibility
review of the executed path; request additional attended checks only for a
specific behavior that changed or remains unverified. Acceptance evidence and
production activation remain separate records.

Accepted Chat and Work activation must persist across builds and releases.
Do not clear accepted evidence or disable a working accepted path without an
explicit user instruction. A package version bump, missing later test results,
or an incomplete scratch run does not revoke acceptance. Renderer builds and
installer/npm staging reject an artifact that drops any of the three accepted
macOS 26.1106.51428 paths. Carry compatible records forward with their original
provenance and fix demonstrated regressions without resetting other paths.

Required Chat checks: existing web-backed conversation, new draft, leave/return, native connected state, End Voice, attended speech both ways, microphone release.

Hashed 26.1106 Chat draft selection uses the Instant Connect conversation store for the adopted backend ID and transcript node, the App location atom as origin, AppNavigation for the route change, and the native `/c/:conversationId` builder. It waits for connected + mapping + current message, then navigates the adopted conversation, not the `local-chatgpt:` Home locator and not `earlyServerThreadId`. Saved UUID composers stay selected. Missing those webpack exports leave START available with manual transcript selection.

Required Work checks: actual voice entry, selected Harness preserved when an external option is actually listed, configured gateway owns the call, connected speech, End Voice and microphone release. A native Codex/gateway pass with **no external Harness listed** is not that preservation check.

Hashed 26.1106 Work uses the overlay fetch wrap and Host CPA gateway. Overlay CDP compares frozen identity and the applied bootstrap digest. Identity plus current-document digest match skips eval. A changed marker, revision, or bootstrap source refreshes the current overlay only while the call is known idle.
